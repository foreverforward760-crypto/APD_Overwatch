Concept briefing · November 2026

APD Overwatch

A proposed group-home operations dashboard concept, exploring whether everyday staff workflows can be made easier to document, review, and coordinate.

What exists today: a browser-based React interface demonstration using synthetic placeholder data. It has no secure backend, live integrations, customer deployment, or independently verified operational outcomes.

The concept and product direction are attributed to the project owner. AI systems generated the implementation code and suggested supporting technical mechanisms.

01 · Current repository

What has actually been built

Browser interface

One large JSX prototype containing screens for resident profiles, medication records, behavior-plan views, incident reports, staff handover, schedules, wallet tracking, and export-oriented workflows.

Synthetic records

Resident, staff, medication, contact, financial, and incident records are demonstration placeholders. They are not real resident records.

No operating backend

No server, database, user authentication, role permissions, secure persistence, audit service, or tested multi-user workflow is included.

The current repository is a visual and workflow prototype. It is not ready to store, process, or transmit real resident information.
02 · Product hypothesis

Workflows worth investigating

The concept is intended to explore a single interface for several operational tasks that group-home operators may currently handle across separate tools.

Staff operations

Shift handover, schedules, staff notes, and task documentation.

Resident records

Resident profile views and links to approved care-plan information.

Medication workflow

Potential documentation and double-checking workflow. No medication administration function is validated or safe to use.

Incident documentation

Drafting and review workflow concepts. No automatic legal or regulatory compliance determination.

Family communication

Possible plain-language updates and approved information-sharing controls.

Exports

Export-oriented interface concepts. No live APD iConnect or EVV connection is established.

03 · Framework

How the 0-9-0 framework fits

The project explores using the owner's 0-9-0 / Stanfield's Axiom of Perpetuity framework as an interpretive vocabulary for patterns and change over time.

Conceptual foundation

The project owner states that the 0-9-0 framework, stage interpretations, and APD Overwatch concept originated with him.

AI-assisted implementation

AI systems generated the software code and proposed technical ways to represent and apply the owner's concepts.

Supporting mechanisms

NSDT and the Container Rule were introduced by AI as supporting implementation mechanisms within the owner's framework, not as independent conceptual origins.

The stage labels and scores in this prototype are project-defined heuristics. They are not validated behavioral, psychological, medical, or risk measurements and must not be used to make care decisions.
04 · Privacy and safety

What must not be done with this prototype

  • Do not enter or connect real resident data or protected health information.
  • Do not use its stage outputs to guide medication, treatment, restraint, Baker Act, placement, seizure response, or emergency decisions.
  • Do not treat sample legal, clinical, or policy language as current or authoritative.
  • Do not represent the interface as HIPAA compliant, APD certified, FDA cleared, or approved for operational use.
  • Do not rely on the export screens as proof of a live connection to APD iConnect, EVV, GPS, or another state system.
Any future deployment involving resident information requires qualified privacy, security, legal, APD, and clinical review before a pilot.
05 · Engineering required

What a real pilot would require

Secure backend

Authenticated accounts, role-based access, encrypted storage and transmission, audit logging, backups, retention, and incident response.

Verified workflows

Operator-led requirements, task testing, error handling, approval steps, and clear separation between draft assistance and official records.

Real integrations

Documented APIs, vendor permissions, test environments, and reconciliation for any EVV, GPS, or iConnect connection.

Independent review

Current legal/regulatory mapping, privacy assessment, security testing, accessibility review, and qualified clinical review where relevant.

06 · Evidence plan

Evidence before performance claims

  • Interview group-home operators and direct-care staff to verify the actual problem and workflow priorities.
  • Test the prototype with synthetic data and measure task completion, error rates, and usability.
  • Define and test every proposed integration independently; do not assume a UI control means an integration exists.
  • Use independent reviewers to assess any proposed behavioral scoring or AI-assisted text feature.
  • Document security, privacy, accessibility, and regulatory findings before considering a live pilot.
No customer outcomes, compliance improvement, fraud reduction, medication-error reduction, or financial return has been demonstrated by this repository.
